## Model size and sampling

The pinned Base and Turbo checkpoints each contain about **30.21 GiB of parameter data at BF16**. The diffusion transformer accounts for 13.25 GiB, the text and vision encoder for 16.33 GiB, and the VAE for 0.63 GiB. Base stores its VAE in FP32 and Turbo stores it in BF16, as verified from their weight headers. The worker loads both in BF16. With `CPU_OFFLOAD=model`, different components occupy the GPU in successive phases. This explains why a 24 GiB GPU can complete some requests. Reference caches, batch size, activations, and decoder workspace determine whether a particular job fits. [Base checkpoint](https://huggingface.co/Qwen/Qwen-Image-2.1/tree/790c92633540aa0cb11d9abf19eb46d861714758) · [Turbo checkpoint](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo/tree/fc13ba1986fcb905854dc8de2f52eee395f49b5b) · [VRAM and offload audit](vram-inference-audit-astra62.md)

## Worker experiments in priority order

1. **Release the prefix key/value (KV) caches when denoising finishes.** The pinned pipeline holds them through VAE decoding. Each square reference prepared at 1024 adds 4,096 tokens and about **2 GiB** of BF16 cache per output in the physical batch, per active guidance branch. Releasing the caches before decode can reduce the decode peak. Measure peak allocated VRAM separately for denoising and decoding, and compare output pixels with a fixed seed. If denoising is the limiting phase, test preparing the same reference at 512 with the output canvas still at 2K. Its cache contribution drops to **0.5 GiB**, with a possible loss of fine reference detail. [Pinned cache and decode code](https://github.com/huggingface/diffusers/blob/da1d3829cf08d4f329b526d89e17cc035c049d8d/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py#L759-L856)
2. **Reuse conditioning across rerolls and edits.** The current worker reuses prompt embeddings and reference VAE encodings across outputs within one job. SGLang also caches conditioning across requests, with a 512 MiB limit per executor. Try a bounded CPU cache on a warm worker. Key entries by the checkpoint, preprocessing settings, and actual ordered reference content, plus prompt text for prompt-dependent entries. Test an identical reroll, a changed prompt with the same reference, and a different reference of the same dimensions. Measure conditioning time and verify cache hits preserve seeded output. [Worker conditioning code](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/deedfcec1b6e5056127837d4fac9a6a51b249619/qwen_worker/conditioning.py) · [SGLang conditioning cache](https://github.com/sgl-project/sglang/blob/main/docs/docs/sglang-diffusion/caching-acceleration.mdx)
3. **Evaluate Cache-DiT for Base.** A community RTX 4090 benchmark measured 40-step text-to-image wall time falling from **23.37 to 9.28 seconds at 1024²** and **97.89 to 35.84 seconds at 2048²**. Cache-DiT skips some denoising work and changes the output. The author timed two runs per setting at 1K and one per setting at 2K. Reproduce on the deployment GPU and test exact text, subject identity, and transparency before offering it as a speed mode. [RTX 4090 results and quality comparison](https://github.com/cyysky/qwen-image-2.1/blob/main/RESULTS.md)
4. **Benchmark compiled attention independently.** Diffusers supports a compiled FlexAttention path for Qwen's prefix processing. Its uncompiled path can exhaust memory at high resolution. Separately, vLLM-Omni measured **6.04 seconds** with compilation and CUDA graphs against **7.74 seconds** with Diffusers on an H200 at 1024² and 50 steps. That comparison changed serving stacks. Test compilation in the existing worker with model offload enabled, and record cold-start cost separately from warm latency. [Diffusers FlexAttention](https://huggingface.co/docs/diffusers/en/api/pipelines/qwenimage21#faster-attention-with-flex_attention) · [vLLM-Omni measurements](https://github.com/vllm-project/vllm-omni/blob/main/recipes/Qwen/Qwen-Image-2.1.md)

## First benchmark on a 24 GiB GPU

Start with one 1024² text-to-image output, one 2048² transparent output, and a three-reference edit. Repeat the edit with four outputs to exercise batching. Hold the GPU, checkpoint revision, prompts, seeds, reference order, offload mode, and output dimensions fixed within each comparison. Vary one setting at a time.

Record cold and warm latency, conditioning time, denoising and decode peaks (allocated and reserved VRAM), and out-of-memory failures. Check delivered image count, dimensions, alpha, exact lettering, and reference identity in the WebUI. The worker's four-output benchmark relaxes the response-size limit, so repeat the delivery check through the normal API. These experiments are pending on the deployment GPU.
