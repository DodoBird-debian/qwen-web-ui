## Offload and estimated use on 24 GiB

With `CPU_OFFLOAD=text_encoder`, the worker keeps the transformer and VAE on the GPU and stages the text encoder there for conditioning. All three components are on the GPU during that phase. The worker moves the encoder back to CPU before denoising. With `CPU_OFFLOAD=model`, component placement changes by phase. The estimates below show how a small request might fit on a 24 GiB GPU with model offload. Actual fit depends on the workload and available memory. [Worker placement](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/runtime.py)

The WebUI estimates below use one 512×512 output, the prompt “A vase,” no references, CFG 1, and prefix KV enabled.

| Offload | Estimated peak | Estimate with 3 GiB safety |
| --- | ---: | ---: |
| `text_encoder` | 33.28 GiB | 36.28 GiB |
| `model` | 20.02 GiB | 23.02 GiB |

Check `CPU_OFFLOAD` in the endpoint startup log and use the GPU's reported capacity when configuring the calculator. The worker and WebUI now default to `model` offload. The worker independently checks live available memory. ## Where the VRAM model needs calibration

- **Conditioning uses the transformer token grid.** A square 1024 reference contributes 4,096 transformer positions and 1,024 language-model image slots. The estimator charges the larger count to the encoder. The worker already tokenizes the prompt in positional preflight. Reuse those counts and budget vision processing separately. Prompt-byte bounds are especially loose for long text. [Memory heuristic](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/memory.py) · [Preflight](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/preflight.py)
- **CFG denoising sums full temporary activation budgets for consecutive passes.** Both prefix caches can be live, but the positive and negative transformer calls run one after the other. Budget the live caches and each branch's own peak workspace. Distinguish initial prefix prefill from later cached steps. [Pinned CFG pipeline](https://github.com/huggingface/diffusers/blob/da1d3829cf08d4f329b526d89e17cc035c049d8d/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py#L759-L816)
- **Decode inherits the whole denoising allowance plus 16 bytes per pixel.** Prefix KV remains live into decode. The VAE has its own workspace and uses slicing and optional tiling. Model the tensors that survive the transition and measure the VAE peak separately. [Memory heuristic](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/memory.py) · [Pinned VAE call](https://github.com/huggingface/diffusers/blob/da1d3829cf08d4f329b526d89e17cc035c049d8d/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py#L836-L856)
- **Sequential offload uses the whole-model budget.** The worker and calculator reserve the same component weights for both methods, although sequential offload stages submodules. Measure both policies before assigning a different budget. [Phase placement](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/runtime.py)

The worker continues to use its conservative admission allowances while these phase peaks remain unmeasured. The checked-in comparison has 48 analytical cases and zero measured GPU peaks. It covers Base with text-encoder offload. A useful calibration workload for 24 GiB is Base or Turbo with the endpoint's actual offload mode, representative reference counts, and peak allocated and reserved VRAM per phase. [Benchmark guide](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/docs/VRAM_MEASUREMENT.md)

## Model size and sampling

The pinned Base and Turbo checkpoints each contain about **30.21 GiB of parameter data at BF16**. The diffusion transformer accounts for 13.25 GiB, the text and vision encoder for 16.33 GiB, and the VAE for 0.63 GiB. Base stores its VAE in FP32 and Turbo stores it in BF16, as verified from their weight headers. The worker loads both in BF16. With `CPU_OFFLOAD=model`, different components occupy the GPU in successive phases. This explains why a 24 GiB GPU can complete some requests. Reference caches, batch size, activations, and decoder workspace determine whether a particular job fits. [Base checkpoint](https://huggingface.co/Qwen/Qwen-Image-2.1/tree/790c92633540aa0cb11d9abf19eb46d861714758) · [Turbo checkpoint](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo/tree/fc13ba1986fcb905854dc8de2f52eee395f49b5b)

| Model | Current behavior | Comparison to run |
| --- | --- | --- |
| Base | The WebUI initializes the step field to 8 and sends that value. The worker defaults to 40 when the field is omitted. | Compare 8 with the ComfyUI workflow's 25 and Qwen's 40 at CFG 1. Score text legibility and reference fidelity alongside latency. [WebUI defaults](../src/api/contract.ts) · [Step selector](../src/components/settings.ts) · [Qwen Base examples](https://huggingface.co/Qwen/Qwen-Image-2.1) · [ComfyUI workflow](https://docs.comfy.org/tutorials/image/qwen/qwen-image-2-1) |
| Turbo | The checkpoint supplies its own distilled eight-step schedule. Passing a step count alone leaves that schedule in effect. | Use the native eight-step schedule and CFG 1 as the fast baseline. [Qwen Turbo schedule](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo#sampling) |

## Worker experiments in priority order

1. **Release the prefix key/value (KV) caches when denoising finishes.** The pinned pipeline holds them through VAE decoding. Each square reference prepared at 1024 adds 4,096 tokens and about **2 GiB** of BF16 cache per output in the physical batch, per active guidance branch. Releasing the caches before decode can reduce the decode peak. Measure peak allocated VRAM separately for denoising and decoding, and compare output pixels with a fixed seed. If denoising is the limiting phase, test preparing the same reference at 512 with the output canvas still at 2K. Its cache contribution drops to **0.5 GiB**, with a possible loss of fine reference detail. [Pinned cache and decode code](https://github.com/huggingface/diffusers/blob/da1d3829cf08d4f329b526d89e17cc035c049d8d/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py#L759-L856)
2. **Reuse conditioning across rerolls and edits.** The current worker reuses prompt embeddings and reference VAE encodings across outputs within one job. SGLang also caches conditioning across requests, with a 512 MiB limit per executor. Try a bounded CPU cache on a warm worker. Key entries by the checkpoint, preprocessing settings, and actual ordered reference content, plus prompt text for prompt-dependent entries. Test an identical reroll, a changed prompt with the same reference, and a different reference of the same dimensions. Measure conditioning time and verify cache hits preserve seeded output. [Worker conditioning code](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/deedfcec1b6e5056127837d4fac9a6a51b249619/qwen_worker/conditioning.py) · [SGLang conditioning cache](https://github.com/sgl-project/sglang/blob/main/docs/docs/sglang-diffusion/caching-acceleration.mdx)
3. **Evaluate Cache-DiT for Base.** A community RTX 4090 benchmark measured 40-step text-to-image wall time falling from **23.37 to 9.28 seconds at 1024²** and **97.89 to 35.84 seconds at 2048²**. Cache-DiT skips some denoising work and changes the output. The author timed two runs per setting at 1K and one per setting at 2K. Reproduce on the deployment GPU and test exact text, subject identity, and transparency before offering it as a speed mode. [RTX 4090 results and quality comparison](https://github.com/cyysky/qwen-image-2.1/blob/main/RESULTS.md)
4. **Benchmark compiled attention independently.** Diffusers supports a compiled FlexAttention path for Qwen's prefix processing. Its uncompiled path can exhaust memory at high resolution. Separately, vLLM-Omni measured **6.04 seconds** with compilation and CUDA graphs against **7.74 seconds** with Diffusers on an H200 at 1024² and 50 steps. That comparison changed serving stacks. Test compilation in the existing worker with model offload enabled, and record cold-start cost separately from warm latency. [Diffusers FlexAttention](https://huggingface.co/docs/diffusers/en/api/pipelines/qwenimage21#faster-attention-with-flex_attention) · [vLLM-Omni measurements](https://github.com/vllm-project/vllm-omni/blob/main/recipes/Qwen/Qwen-Image-2.1.md)

5. **Choose the largest batch that fits.** The worker currently chooses between the full batch and one output at a time. The four-output reference example above admitted two outputs under a simulated 48 GiB memory budget. Running `2+2` would reduce four pipeline calls to two and preserve the seed sequence. Benchmark latency and throughput on the GPU. [Batch grouping](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/service.py)
6. **Capture only the final pre-normalization encoder output.** The encoder retains all hidden states for a consumer that reads only the last one. Capture that output directly and compare embeddings for text and image prompts before deploying. [Pinned encoder path](https://github.com/huggingface/diffusers/blob/da1d3829cf08d4f329b526d89e17cc035c049d8d/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py#L293-L319)
7. **Move final CPU output fitting outside the inference lock.** Compression and resizing can repeat inside the same lock that protects the GPU pipeline. Keep any per-pass delivery check needed to stop wasteful sequential generation, and release the lock for final CPU-only fitting. [Service lifecycle](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/service.py) · [Transport fitting](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/main/qwen_worker/transport.py)

## First benchmark on a 24 GiB GPU

Start with one 1024² text-to-image output, one 2048² transparent output, and a three-reference edit. Repeat the edit with four outputs to exercise batching. Hold the GPU, checkpoint revision, prompts, seeds, reference order, offload mode, and output dimensions fixed within each comparison. Vary one setting at a time.

Record cold and warm latency, conditioning time, denoising and decode peaks (allocated and reserved VRAM), and out-of-memory failures. Check delivered image count, dimensions, alpha, exact lettering, and reference identity in the WebUI. The worker's four-output benchmark relaxes the response-size limit, so repeat the delivery check through the normal API. These experiments are pending on the deployment GPU. [Worker measurement protocol](https://github.com/DodoBird-debian/qwen-image-2.1-worker/blob/deedfcec1b6e5056127837d4fac9a6a51b249619/docs/VRAM_MEASUREMENT.md)

## Delivery and browser follow-ups

1. **Offer exact-size downloads beyond the inline cap.** Store original outputs in private object storage keyed by job and seed. Return short-lived signed links plus inline previews, with explicit cleanup and expiry. Independently benchmark an alpha-preserving WebP fallback for transparent requests to measure how often it can avoid JPEG flattening.
2. **Resume a series as a collection.** Persist its plan, accepted job IDs, parameter labels, and completed cells. Rebuild the comparison grid after reload and let the user explicitly select missing cells for a new request. Existing per-job history can still recover downloaded frames individually.
3. **Stream large browser exports.** Move ZIP assembly off the UI thread and stream entries to disk where supported. Offer bounded split archives elsewhere. The current 100 MB cap still requires simultaneous allocations for selected images and the archive. [Archive assembly](../src/export/archive.ts)
4. **Measure fidelity, throughput, and cancellation on Base and Turbo.** Extend the 24 GiB benchmark above with high-entropy transparent PNG inputs and a controlled cancellation. Compare retained count, dimensions, alpha, and p50/p95 inference and encoding time at the same seeds, dimensions, and payload cap.
